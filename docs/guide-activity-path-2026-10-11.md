## Five actual milestones

1. Explicitly open a Grouping, after native disclosure completion, or successfully
   create one. The session token is captured before disclosure/creation.
2. Select actual Groups, not Participants or source members.
3. In the native Group-context destination dialog, explicitly choose a positive
   existing Grouping. Zero means removal and is never accepted here.
4. Check destination and original-membership removal, then explicitly confirm.
   The previously validated bridge saves immutable expected IDs only after the
   complete native batch succeeds, using its original canonical session token.
5. Explicitly close/reopen that same destination's native disclosure and verify
   all expected Group IDs belong to that rendered Grouping. Verification follows
   Motion completion, rejects another Grouping, hidden/missing Groups and obsolete
   sessions. Guide presentation only focuses/marks the destination; it cannot
   submit or verify a command.

Both languages explain missing prerequisites, mobile Group selection, default
preservation versus removal, non-atomic per-Group requests and the subsequent
separate Grouping choice in Moodle activity settings. The Guide does not configure
an activity or automatically create course data.

start compact as well as resizing a desktop page. Wait actual cue/Motion readiness
rather than inventing delays. QA cleanup must not reinitialize a path before
native selection cleanup. Respect file-specific Git EOL attributes before making
the recovery snapshot. These prevent repeat diagnostic cycles; provider token
and monetary totals are unavailable, so no numerical quota saving is claimed.
