# EasyStud functional test protocol

## Purpose and supported targets

This protocol translates the EasyEdu platform quality gates into checks owned
by `local_groupimport`. The plugin declares Moodle 5.1 as its minimum version.
The first platform promotion target is Moodle 5.2; release validation must cover
both the declared minimum and the current matrix target.

The protocol does not make local Playwright audits mandatory. A test becomes a
required CI gate only after its fixtures and timing are deterministic on the
target runner.

## Canonical fixture profile

The minimal stable Behat profile is generated by Moodle:

- course `ES101`;
- editing teacher `teacher1`;
- six enrolled students `student1` through `student6`;
- groups `ES Group A`, `ES Group B` and `ES Empty Group`;
- groupings `ES Assignment` and `ES Empty Grouping`;
- students 1-3 in Group A and students 4-5 in Group B;
- Group A and Group B in the Assignment grouping;
- `local_groupimport/enablesimplifiedview` explicitly enabled.

This profile supports navigation, compact/full participant cards, basic
selection, filtering and non-destructive view switching. Destructive tests must
create their own scenario data and must not share state with another scenario.

## Interaction rules

### Selection

Verify that:

- selecting one participant may reveal its details;
- selecting multiple participants keeps cards compact;
- participant, group, grouping and nested member selections are mutually
  exclusive;
- disabled selectors are visually and semantically disabled;
- Clear selection resets cards, buttons, menus and expanded groupings;
- changing workspace clears the previous selection.

### Drag and drop

EasyStud uses native HTML5 drag events. Playwright `dragTo()` is not a reliable
substitute for these handlers. Automated tests should dispatch
`dragstart`, `dragover`, `drop` and `dragend` with one shared `DataTransfer`.

For each draggable flow, also test the action-button/modal alternative. Touch
users must never be required to drag an object.

### CRUD and destructive actions

Each scenario creates unique group and grouping names. Confirm:

- duplicate names return a Moodle-derived error without a page reload;
- create/duplicate/rename update every relevant list dynamically;
- deletion requires confirmation when the object contains children;
- deletion removes stale copies from nested views;
- success toasts report affected and already-existing item counts.

### Context Copy and Paste

Copy/Paste is additive and is not an alias for Move. With isolated scenario
data, verify that:

- pasting a Participant into a destination Group preserves every prior Group
  membership and adds exactly the destination;
- pasting a Group into a destination Grouping preserves every prior Grouping
  assignment and adds exactly the destination;
- repeating the same Paste creates no duplicate and reports an existing item;
- the live cards, counts and entity detail modals rehydrate without a reload;
- the separately labelled Move flow retains its explicit origin-removal
  behavior.

### Mass import

For the shared navigation consumer, run only
`mass-import-navigation-audit.spec.js` through the supervised saved-credential
wrapper after one-test discovery and GroupImport runtime-lease acquisition. It
is read-only: it must prove that the shared rail replaces the legacy header
action row, preserves Simplified student management, current Mass group import,
Download example and Import history, and omits Back to course. At 390 px it
must prove compact open/close, history modal open/close, focus return to the
visible handle, no participant or Guide clone in this consumer, no horizontal
overflow and no console/page errors. While the panel is open, the EasyStud
trigger itself must be hidden so it cannot overlap Moodle's native drawer
control. Register its screenshots outside Git with the runner manifest. Human
visual review still decides the desktop page-header action relationship.

Cover CSV and XLSX independently. Preview must not mutate course data. Validate:

- mixed enabled user identifiers;
- unknown and ambiguous identifiers;
- duplicate users, groups and groupings;
- rows with recoverable formatting errors;
- replace-file flow;
- selected/deselected preview rows and search;
- report counts and downloadable evidence;
- history restore to a known prior state.

Restore tests are destructive and remain opt-in until the platform provisions a
disposable database snapshot per run.

## Missing deterministic fixtures

The following are not currently present and must be added before their tests
become matrix gates:

- canonical CSV and XLSX files containing valid, unknown, duplicate and
  ambiguous identifiers;
- custom user profile fields configured as unique identifiers;
- users with identical first or last names but different unique identifiers;
- a capability matrix for manager, editing teacher, non-editing teacher and
  student;
- a large course fixture that deterministically triggers every pagination
  threshold;
- guide fixtures for empty course, locked slide and unlock-path states;
- import-history records and a disposable restore snapshot;
- translated fixtures for at least English and French.

Do not encode local course ID `5`, local credentials or production-derived data
in repository fixtures.

## Data reset

- Behat scenarios rely on Moodle scenario isolation and generators.
- PHPUnit uses `resetAfterTest()`.
- Non-destructive Playwright audits may use a prepared local course.
- Destructive Playwright audits require an explicit opt-in variable and a
  disposable fixture course or restore point.
- Never point destructive tests at a shared or production site.

## Local commands

Repository-owned checks:

```powershell
.\tools\release\validate-plugin.ps1
cd tools/playwright
npm ci
npx playwright test accessibility-smoke.spec.js
npx playwright test card-title-selection-audit.spec.js
npx playwright test responsive-audit.spec.js
```

Target mature Moodle coding gate:

```bash
moodle-plugin-ci phplint
moodle-plugin-ci phpcs --max-warnings 0
moodle-plugin-ci phpdoc --max-warnings 0
moodle-plugin-ci validate
moodle-plugin-ci savepoints
moodle-plugin-ci mustache
moodle-plugin-ci grunt --max-lint-warnings 0
moodle-plugin-ci phpunit
moodle-plugin-ci behat --profile chrome
```

Record every skipped command with the missing dependency or fixture. A skipped
gate is not a pass.

## Platform matrix promotion backlog

Promote in this order:

1. PHPUnit feature-flag and navigation helper tests on Moodle 5.1 and 5.2.
2. Behat navigation/view-switch smoke.
3. Behat plugin-region accessibility smoke.
4. Playwright axe smoke with a platform-owned authenticated fixture.
5. Selection exclusivity and non-drag movement scenarios.
6. Group/grouping CRUD scenarios.
7. Mass import service-level identifier data providers.
8. Disposable mass import history restore scenario.
9. Responsive long-press/action-tray scenario once timing is stable on Linux.
10. Guide highlight/checklist lifecycle scenario after browser parity is
    confirmed on both matrix targets.
