# First-visit workspace controls and Behat density

The first-visit Guide invitation used its below-launcher slot whenever that
slot fit the viewport. It could therefore cover the workspace view tabs on a
fresh installation. The consumer now supplies welcomeAvoidTargets for its
desktop/mobile view controls. The shared Guide chooses the above-launcher slot
when the lower slot overlaps a visible protected control and the upper slot
fits without that overlap. The viewport clamp, arrow and unconfigured consumers
keep their previous behavior. This is a placement correction, not a test scroll
or a hidden invitation. The Kit source and embedded mirror carry the same change.

Participant density changes after Motion.swap finishes its exit phase. An
immediate negative Behat existence assertion can run while the old class still
exists. The feature now waits for the exact same final class absence, then keeps
its original assertion and selection checks. No expected density, duration,
Motion level or product state changes. This is synchronization, not obsolescence.
