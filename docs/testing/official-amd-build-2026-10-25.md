# Official Moodle AMD build

## Release contract

Release AMD artifacts are the output of Moodle's **official `grunt amd`**,
including its Babel plugins, Rollup pass, Terser plugin and sourcemaps. Equivalent
JavaScript is insufficient: moodle-plugin-ci 4.5.11 removes `amd/build`, rebuilds
from `amd/src`, and compares every generated JS/map byte with the committed copy.
Its AMD working directory is the plugin's `amd` directory, not `admin/tool/task`.

Use an installed Moodle build checkout matching the CI branch and lockfile:

```text
node tools/release/build-amd-official.cjs MOODLE_BUILD_ROOT
node tools/release/build-amd-official.cjs MOODLE_BUILD_ROOT --check
```

The helper uses the pinned Node version and delegates to the unmodified Moodle
Grunt task with `--max-lint-warnings=0`. It builds all modules in an isolated
temporary Moodle skeleton; it does not install packages, change a served Moodle,
write sources or modify the supplied build checkout. Only staged source copies
are normalized to LF, matching Git checkout on Linux. This preserves Windows
working-file line endings while making embedded `sourcesContent` reproducible.
`--check` never writes plugin artifacts and fails on any byte difference. Missing
or obsolete modules fail inventory validation rather than being silently deleted.

Use the dependency versions installed from Moodle's `npm-shrinkwrap.json`. A
different Moodle branch, dependency lockfile or Browserslist database can change
the result. The helper reports the lockfile SHA256. It does not certify an arbitrary
dependency installation just because a lockfile exists beside it.

## Why the older builders diverge

The historical `build-sm-amd.js`, `build-guide-amd.cjs` and other individual
`build-*-amd*` scripts use several handwritten compilation/wrapper paths. They
remain unchanged, including their architectural guards, for historical source
checks. **Their output is not the release authority.** After using one of them,
run the official full builder and `--check` before committing AMD artifacts.
Do not alter product JS or weaken lint to satisfy the stale-file gate.

The official pipeline adds Moodle's module-name/default-export plugin and runs
Rollup (`format: esm`, `context: window`, `treeshake: false`) before Terser
(`mangle: false`). Consequences include relative AMD imports and Babel's lazy
dependency factories instead of handwritten eager wrappers, Rollup removal of
redundant strict directives, Babel lowering against Moodle's Browserslist, and
Rollup-composed maps containing original source text. A direct Babel/Terser call
or textual module-name replacement does not reproduce this pipeline.

The 2026-10-25 regeneration covers 65 modules / 130 files, with no `amd/src`
change. The reproduction uses Moodle `MOODLE_405_STABLE` at
`cae172ee4aeec1d7a6eaba7bb5ae12a5f0fe3772`, Node 22.11.0, Babel 7.17.5,
preset-env 7.16.11, Rollup 2.67.3, grunt-rollup 11.9.0,
rollup-plugin-terser 7.0.2 and Terser 5.11.0. The lockfile SHA256 is
`7c4461bd11aabb43037c90699bb93bee67bbaeb63980d4b567e3885bde7da247`.
CI used Node 22.23.4, within the same official Moodle Node 22 range; the local
builder deliberately retains this project's exact Node 22.11.0 pin.

## Validation boundaries

- Rebuilding from an empty staging build directory and `--check` verifies all
  generated bytes, including sourcemaps, with zero ESLint errors/warnings.
- Existing generated Motion, Guide lazy API and page-bootstrap behaviour checks
  exercise actual built code. Filter-engine and escaping checks remain intact.
- `test-choice-amd-exports.js` assumes zero dependencies and a returned facade.
  Official Babel emits an `exports` dependency plus the actual Motion import.
  Its format-only assertion is obsolete; it is retained unchanged in this lot.
  Validate public exports through RequireJS rather than weakening the assertion
  or restoring a noncanonical build wrapper.
- Native read-only before/after verification, evidence and CI run results are
  recorded in the external Grunt build report. A deterministic local build alone
  does not imply a complete native or remote CI pass.

No PHP, product JS, Mustache, Behat feature or existing test is changed by this
build-only correction. No production/staging deployment is part of this lot.
