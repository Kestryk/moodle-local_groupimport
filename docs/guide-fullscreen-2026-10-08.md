# Guide desktop fullscreen — G10-H

EasyStud opts into the canonical Guide fullscreen lifecycle through manage.php.
EN/FR labels and the existing adapter are product-owned; all presentation and
controller rules are in the shared Kit. The helper is embedded and wrapped in
the existing AMD module by the allowlisted synchronization script; it does not
introduce a separate Moodle loader or a second guide engine.

The browser owns fullscreen. Desktop button only, real user gesture, normal
modal fallback on refusal. First Escape exits fullscreen and keeps the Guide
open on the same slide. Close and Show in interface await exit; target focus
never occurs behind the fullscreen top layer. Mobile has no fullscreen action.

Foundation Small Enter/Exit controls preserve linked Secondary S and canonical
Expand/Compress glyph providers. Library/Standard saved4 roots/28 descendants;
Guide two linked controls saved2 roots/14 descendants. External rasters inspected.
This is bounded composition proof, not a whole-guide visual acceptance.

Isolated actual built-consumer Chrome tests pass normal/reduced native entry,
Escape/close, Show in interface target focus, refusal feedback and phone hiding.
Native Moodle scenario: tools/playwright/guide-fullscreen-native.spec.js,
local-supervised candidate. It blocks course writes and uses the already-seen
QA account; it does not reset the welcome state or manufacture a guided path.
Native preview/proof pending. Common introduction/curriculum and the combined
human checklist remain open.
