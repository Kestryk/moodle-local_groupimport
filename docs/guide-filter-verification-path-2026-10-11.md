## Behaviour

`verify-with-filters` is a new four-step optional path on search-filter-select:
open Participant More filters, apply a non-empty filter/search with results,
select exactly those results, then clear all Participant selection. Every
step uses the next-unfinished native event gate and explicit predecessor.
The existing twelve reading IDs/presentation key, seven other paths and all
historical completion/storage keys remain unchanged. There are now seven
visible invitations and eight path definitions in the candidate.

Open completion follows the native expand onComplete, not closing filters or
an arbitrary Guide delay. Search/role/group/grouping events complete the second
step only after native filtering. Result selection follows native action
refresh and uses getSelectableResultItems, including matching off-page cards.
An excluded selected Participant prevents completion even if all filtered
results are selected. Clear completion requires zero selected Participants.
No Guide control submits a membership command. Filters are not silently reset
when starting/reviewing the path.

The explicit Participant opener checks the active mobile/desktop workspace
before changing it, so reviewing a step does not reapply an already-active mode
and erase selection. The second-step opener only reveals the original filters
when closed. The guide targets the actual scoped result pager and the existing
desktop Clear/mobile action proxy. No generic old filter-complete event is
reused as proof of the new workflow.
